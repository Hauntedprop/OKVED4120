# Анализ строительной отрасли (ОКВЭД 41.20)

Лабораторная: собрать датасет самому и оценить перспективность отрасли
жилищного и нежилого строительства по данным ФНС.

Вся работа в блокноте
[Анализ строительной отрасли ОКВЭД 41.20.ipynb](Анализ%20строительной%20отрасли%20ОКВЭД%2041.20.ipynb):
код, выводы ячеек и текст там же.

## Что сделано

1. Из реестра МСП ФНС (603 520 строк) отобрал 10 573 компании: юрлица, малые и
   средние, ОКВЭД 41.20 и 41.2.
2. Спарсил отчётность с bo.nalog.gov.ru: 58 342 строки "компания-год" за
   2020-2025, нашлась у 99,1% компаний.
3. Дособрал баланс, чтобы обосновать замену EBITA на EBIT числом.
4. Собрал сбалансированную панель: 7 736 компаний, у которых есть все 6 лет.
5. Посчитал EBITA по годам с поправкой на инфляцию.
6. Построил графики роста чистой прибыли для N = 1, 3, 5.
7. Сделал карту топ-500 компаний по выручке.

## Выводы

Суммарные показатели растут, а у обычной компании дела идут хуже:

* суммарная EBITA за 2020-2025 выросла на 87%, в ценах 2020 года на 24%
* медианная EBITA при этом выросла на -0,6%, то есть реально минус треть
* доля прибыльных компаний упала с 87% до 76%
* медианная рентабельность по EBITA около 3% и не растёт
* 2025 год отрицательный по всем ключевым метрикам
* инфляцию по чистой прибыли обогнали только 37% компаний

Разрыв между суммой и медианой возник не из-за крупных компаний: топ-10 дают
всего 3,9% выручки панели. Сумму вытянул нижний сегмент, у которого была почти
нулевая база.

## Как запустить

```bash
pip install pandas numpy matplotlib plotly requests openpyxl
jupyter notebook "Анализ строительной отрасли ОКВЭД 41.20.ipynb"
```

Долгие шаги обёрнуты в проверку `os.path.exists`, так что при наличии CSV в
папке блокнот читает их и не ходит в API заново. Полный пересбор с нуля занимает
около 10 минут: 6 минут на чтение xlsx и 3,5 минуты на обход 10 573 компаний в
4 потока.

Карты интерактивные, поэтому внутри блокнота на GitHub они не отображаются.
Для них есть html-файлы, либо можно запустить блокнот локально.

## Что оказалось неочевидным в данных

1. Код 2330 пуст у 58% строк, но это не пропуск, а отсутствие кредитов. Если
   оставить NaN, половина выборки пропадёт на `2300 + NaN`.
2. У 39% строк нет кодов 2200 и 2300: малые предприятия сдают упрощённую форму
   2. Для них EBIT считается через прочие доходы и расходы, формула сходится у
   96,6% строк.
3. Знак кода 2410 непостоянен: у 92% строк минус, у остальных плюс, причём у
   одной компании он меняется по годам.
4. Nominatim после 50 запросов начал отдавать пустые ответы на всё подряд. Это
   был отказ 429, а не отсутствие городов. Перешёл на Photon.
5. Адреса в БФО расходятся с реестром у 34 компаний из 500, поэтому адреса взял
   из реестра.
6. Рост с -500 до +1000 обычная формула показывает как -300%. Пришлось делить
   компании на три группы по знаку базы.
7. В реестре только действующие компании, так что обанкротившиеся в выборку не
   попали и реальная картина отрасли хуже полученной.
